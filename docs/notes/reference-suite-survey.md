# Reference examples: measured compile survey

Generated by `tests/upstream/reference-report.rb`. These are compile-only observations, not conformance assertions or runtime passes.
All extracted C++ examples were surveyed with system GCC 15.2.0; language examples were also compiled to objects on the three nfcxx routes.
cppreference uses C++23 throughout. cpprefjp language examples use their page standard; library examples use C++23.
Newer-draft examples, fragments, intentional errors and library limitations can cause rejection. `mode-unavailable` means the compiler does not recognize the requested dialect flag.
The per-invocation budget was 20 seconds, except the corrected sizeof/sizeof... cases rerun with 60 seconds. Timeouts under this budget are not proof of missing support.

The language rows are subsets of the all-example inventories, not additional examples. Host syntax acceptance and nfcxx object compilation test different stages; neither executes unreviewed source.

cppreference is usable as a large corpus of positive examples after classification. Acceptance is an upper bound on candidates for reviewed runtime checks, not a count of trustworthy regression assertions.
Its examples do not provide systematic negative/diagnostic coverage, complete per-paper coverage, or portable exact output for every example.
The HTML inventory takes the first code block in each t-example container; multi-block or multi-file examples need manual assembly.
cpprefjp provides explicitly tagged examples and standard-specific language pages, making extraction and mode selection easier; a tag still does not establish deterministic behavior or a portable oracle.

Runtime checks remain explicit: ten cppreference and four cpprefjp examples, four GCC programs, and three LLVM programs. Clang uses five native lit tests; EDG uses its native regression harness.
