# libclang on the EDG front end (libclang-edg)

Status: **experimental, declarations only.** `libclang-edg.so` exports libclang's C API. Its declaration cursors come
from EDG's own IL, so the cursor kinds, names, positions and parent/child structure of a file's declarations match
libclang 18 on the cases in `tests/libclang-edg/cases/`. Everything else is a stub that says so on stderr.
`clang.cindex` (the libclang Python binding, 18.1.8) imports against it with its default checks and walks the same
declarations with the same result.

## Pieces

| Path | What |
| --- | --- |
| `be/nfcxx_decl.c` | The back end. `back_end()` lists the declarations of the main file as tab-separated records (format in the file's header), to stdout or to the stream `nfcxx_decl_out`. |
| `be/nfcxx_edg_entry.c` | `nfcxx_edg_run(argc, argv, out)`: one compilation of the front end built as a library (EDG's callable front end), with the records written to `out`. |
| `scripts/setup-libclang-edg.sh` | Builds `build/libclang-edg/cmake/bin/cpfe`: EDG with `nfcxx_decl.c` as its back end, and the same front end as position-independent objects with the entry point, `build/libclang-edg/cmake/src/nfcxx-so/libedgfe-pic.a` (`LIBCLANG_EDG_IN_PROCESS=0`: cpfe only). `3rd/edg` is not modified. |
| `scripts/libclang-cursors` | Runs that `cpfe` on one file with the host's library options (as `scripts/pathb-dump` does) and prints the records. |
| `lib/libclang-edg/clang_edg.c` | The C API: parses by calling the front end linked into the library (or by running `libclang-cursors`), builds a tree of cursors, serves the API from it. |
| `lib/libclang-edg/include/clang-c/Index.h` | The types, enum values and the hand-written prototypes of the implemented functions (libclang's ABI). |
| `lib/libclang-edg/include/clang-c/Index_api.h`, `lib/libclang-edg/generated/stubs.c` | Generated by `scripts/gen-libclang-edg-api.py` from `clang.cindex`'s function table: a prototype for every function the binding uses, and a stub for each one not implemented. |
| `scripts/build-libclang-edg.sh` | Builds `build/libclang-edg/libclang-edg.so`: with the archive, the front end inside it and the options of `libclang-cursors` fixed in `build/libclang-edg/edg_args.h`; without it, a library that runs `libclang-cursors`. |
| `tests/libclang-edg/run.sh` | Differential test: `walk.c` (C API only) and `cindex_walk.py` (the binding) run on `cases/*.cpp` against the system libclang; the differences must be the ones in `known/`. |

Run: `scripts/setup-libclang-edg.sh && scripts/build-libclang-edg.sh`, then `tests/libclang-edg/run.sh`. The
reference is the first `libclang.so` found under `/usr/lib/llvm-*` (or `LIBCLANG_ORACLE`). The Python part needs the
binding (`pip install clang==18.1.8`, or `LIBCLANG_EDG_PYTHON=DIR` for a directory holding the `clang/` package).
`LIBCLANG_EDG_RUNNER` at run time makes the library run that `libclang-cursors` (a separate process) instead of the
front end it holds, or the one it was built with.

## How it works

- **The front end is in the library.** EDG's front end is callable when it is built with `EDG_MAIN` defined
  (`MAKE_FRONT_END_CALLABLE`, `basics.h`): `EDG_MAIN` returns the exit status, a catastrophic error longjmps back to
  it, and `fe_cleanup` frees the compilation, so it can be called again. `setup-libclang-edg.sh` builds that front end
  (`EDG_MAIN=nfcxx_edg_main`, `-fPIC`, hidden visibility, cpfe's macro configuration) with `nfcxx_decl.c` and
  `nfcxx_edg_entry.c` into an archive, and `build-libclang-edg.sh` links it into `libclang-edg.so`, which exports the
  C API and nothing of EDG. `clang_parseTranslationUnit` calls `nfcxx_edg_run` with the command line of
  `libclang-cursors`: the host's system include directories, GNU version and the base directory, found when the
  library is built (`edg_args.h`; `--edg_base_dir` in place of the script's `cd`), then the caller's `-std=c++NN`,
  `-I` (made absolute: the front end runs with `--wdir /`), `-D` and `-U`, and the file. The records go to a memory
  stream. EDG's state is global, so parses are serialized with a mutex. The handlers that EDG sets for `SIGINT`,
  `SIGTERM`, `SIGXFSZ` and `SIGSEGV` on its first call are the client's again after each call. Diagnostics go to the
  client's stderr, as they did from the process. A crash of the front end is a crash of the client: for isolation,
  `LIBCLANG_EDG_RUNNER=scripts/libclang-cursors` runs it as a process (`popen`) as before, which is also what a library
  built without the archive does.
- **The back end is EDG's C++-generating configuration** (`linux-gcc-release/cpfe-cp`, `BACK_END_IS_CP_GEN_BE=1`)
  with `nfcxx_decl.c` in place of its `back_end()`. That configuration keeps two lists the walk needs: the per-class
  member-declaration list (`MAINTAIN_CLASS_MEMBER_LIST=1`, in declaration order) and the source sequence lists. IL
  lowering is off, because EDG rejects the source sequence lists with it.
- **Names and parents.** `source_corresp.name` is the mangled name for many entities; the source name is
  `unmangled_name_or_mangled_encoding` when `name_has_been_mangled` is set. EDG lists a class member both in its class
  and at file scope, and namespace members at file scope, so a parent comes from the scope being walked (or the
  class's member list), not from `parent_scope`, and an entity is listed once.
- **Templates.** A template function's prototype instantiation (`is_prototype_instantiation`) is the pattern, listed
  as `FunctionTemplate`; other `is_template_function` routines are instances and are not listed. A class with
  `is_prototype_instantiation` is a `ClassTemplate`; a class with `is_template_class` and without it is an instance. EDG gives
  instances the template's position, so listing them would print each template twice.
- **Two EDG build details.** `folding.c` calls `mangled_typeinfo_string`, which `lower_name.h` declares only with IL
  lowering on, and the configuration has lowering off. The build tree's copy of `folding.c` (never the submodule's)
  gets the prototype. The Itanium ABI flag (`IA64_ABI=1`, which Linux sets in `support/platform/linux/base`) is set so
  the function is declared at all. `cp_gen_be.c` stays compiled (`expr_has_comma_operation` lives there) with its
  `back_end` renamed.
- **Kinds and ABI.** The kind values and the `CXCursor`/`CXString`/`CXSourceLocation`/`CXSourceRange`/`CXType`/`CXToken`
  layouts are libclang's. `Index.h` checks them against the binding's ctypes sizes at compile time (`_Static_assert`
  in `Index_api.h`), and `kind` values and spellings are checked by the differential test.

## Coverage

Implemented (31 of the binding's 174 functions, plus the libclang functions the binding does not use): index and
translation unit lifecycle, `clang_visitChildren`, cursor kind and spelling, semantic and lexical parent, cursor
location, extent (begin and end are both the cursor's position), spelling, instantiation, expansion, file and
presumed locations, `clang_getFileName`, range start, end and equality, `clang_Cursor_getTranslationUnit`, the
cursor-kind predicates, strings and the version string.

Stubbed: every other function of the binding's table. A stub prints `libclang-edg: NAME is not implemented yet`
once on stderr and returns zero (`NULL`, `0`, or a zeroed struct, so an invalid type). Types, tokens, diagnostics,
code completion, references, expressions and the rest are not implemented.

## Known differences from libclang 18

Checked by `tests/libclang-edg/run.sh`: each one is in `known/` and nothing else may differ.

- **Parameters of a declaration without a body are not listed** (`void f(int x);`). EDG keeps those names only in
  rare cases, so the IL does not have them. Parameters of definitions are listed.
- **An alias declaration (`using A = B;`) is a `TypedefDecl`**; libclang has a `TypeAliasDecl`. EDG's alias flag is in
  the source-sequence record, not on the type.
- **A reopened namespace is listed once**: EDG has one entity for all declarations of a namespace.

Not checked, and expected to differ: template parameters (`TemplateTypeParameter`) are not children of a template;
`clang_getCursorExtent` gives a point, not a range; a syntax error makes `clang_parseTranslationUnit` return `NULL`
where libclang returns a translation unit with diagnostics; declarations from headers are not visited (libclang
visits them and `clang_Location_isFromMainFile` tells them apart); an out-of-class definition of a member of a class
declared in a header is listed at file scope.

## Next

1. Types: `clang_getCursorType`, `clang_getTypeSpelling`, `clang_getTypedefDeclUnderlyingType` from EDG's `a_type`.
   The binding's `Cursor.type` and most scripts need them.
2. Parameters of declarations: if EDG can keep the prototype's names (the prototype scope), the first known
   difference goes away.
3. Headers: a flag to visit declarations of included files, and `clang_getIncludes`-style inclusion data.
4. References and expressions (`clang_getCursorReferenced`, `CallExpr`, `DeclRefExpr`), from the IL's name references.
